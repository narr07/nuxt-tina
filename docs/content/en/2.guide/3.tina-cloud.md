## Setting up Tina Cloud

1. Create a project at [app.tina.io](https://app.tina.io) and connect your GitHub repo.
2. Copy the **Client ID** and **Read-only Token** from the project dashboard.
3. Save them as environment variables:

```env
NUXT_TINA_CLIENT_ID=<your-client-id>
NUXT_TINA_TOKEN=<your-token>
```

4. Build the production admin (not local dev mode):

```bash
npx tinacms build
```

`tinacms dev` **always** shows a "You are in local mode" banner regardless of `clientId`: that's not a bug, it's the CLI's behavior. The real Tina Cloud login only shows up in a production build (`tinacms build` without `--local`, then deployed or run via `nuxi build && nuxi preview`).

## Two editing modes

`nuxt-tina` doesn't "replace" Tina's built-in editor. These two modes run independently:

| Mode | URL | Needs our bridge? |
| --- | --- | --- |
| **Basic CMS** (stable) | `/admin#/collections/<name>/edit/<file>` | No: the form reads/writes directly to the local data layer |
| **Visual/contextual** (experimental) | `/admin#/~/<page-path>` | Yes: uses `useTina()` + `data-tina-field` |

If visual editing feels unstable in your project, basic CMS mode still works fully as a fallback.
