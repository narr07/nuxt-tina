# `tina` in `nuxt.config.ts`

Every module option is set under the `tina` key:

```ts
export default defineNuxtConfig({
  modules: ['nuxt-tina'],
  tina: {
    clientId: process.env.NUXT_TINA_CLIENT_ID,
    token: process.env.NUXT_TINA_TOKEN,
    branch: 'main',
    visualEditing: true,
    media: {
      publicFolder: 'public',
      mediaRoot: 'uploads',
      provider: 'tina',
    },
    enabled: true,
  },
})
```

All options are optional — the module falls back to sane defaults, including reading credentials from the environment. See [Installation & Setup](/getting-started/installation) for the env var list.

## Options

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `clientId` | `string` | `NUXT_TINA_CLIENT_ID` \| `TINA_CLIENT_ID` env var | Your Tina Cloud client ID. |
| `token` | `string` | `NUXT_TINA_TOKEN` \| `TINA_TOKEN` env var | Tina Cloud read-only token (kept server-side only). |
| `branch` | `string` | `NUXT_TINA_BRANCH` \| `HEAD` env var, else `'main'` | The Git branch content queries target. |
| `tinaPath` | `string` | `'tina'` | Where the Tina config folder lives, relative to the project root. |
| `visualEditing` | `boolean` | `true` | Enables the client-side iframe postMessage bridge plugin. |
| `media.publicFolder` | `string` | `'public'` | The folder public web assets live in. |
| `media.mediaRoot` | `string` | `'uploads'` | The subfolder uploaded images are stored under. |
| `media.provider` | `'tina' \| 'cloudinary'` | `'tina'` | The media store backend. `'cloudinary'` registers the `/api/cloudinary/**` route — see [Media & Cloudinary](/guide/media). |
| `enabled` | `boolean` | `true` | Disables the module entirely when `false`. |
