## Build command

Beda sama dev (`tinacms dev -c "nuxt dev"`, yang selalu jalan di mode lokal), build production butuh `tinacms build` (bukan `dev`) biar admin-nya dibangun jadi static bundle yang konek ke Tina Cloud, bukan mode lokal:

```bash
tinacms build && nuxt build
```

`tinacms build` bikin `tina/__generated__/client.ts` (dipakai server route kamu) dan admin production bundle (di-serve dari `public/admin/`), terus `nuxt build` bangun aplikasi Nuxt-nya sendiri.

## Environment variables

Set ini di hosting provider kamu (environment production dan preview):

```env
NUXT_TINA_CLIENT_ID=
NUXT_TINA_TOKEN=
NUXT_TINA_BRANCH=main
```

Kalau kamu juga pakai Cloudinary:

```env
NUXT_TINA_CLOUDINARY_CLOUD_NAME=
NUXT_TINA_CLOUDINARY_API_KEY=
NUXT_TINA_CLOUDINARY_API_SECRET=
```

Lihat [Media & Cloudinary](/guide/media) buat gambaran lengkapnya — Cloudinary butuh beberapa env var lagi selain ini, dibaca sama CLI `tinacms` dan `next-tinacms-cloudinary` dengan konvensi naming masing-masing.

## Yang perlu dicek pas deploy beneran

- Pastiin `/admin/index.html` ke-serve dengan benar sebagai static asset dari `public/admin/` di environment hosting provider kamu.
- Pastiin login Tina Cloud-nya beneran muncul (bukan "local mode") — itu sinyal utama kalau build production-nya udah dikonfigurasi dengan benar, sama seperti yang udah diverifikasi lokal di [Tina Cloud & Mode Editing](/guide/tina-cloud) lewat `nuxi preview`, tapi belum di hosting provider yang beneran.
- Kalau kamu deploy di dalam monorepo (module + app di repo yang sama, atau `tina/config.ts` di luar root app-nya), setting root directory / build command di provider kamu kemungkinan perlu disesuaikan biar `tina/config.ts` dan `content/` bisa dijangkau dari build step-nya.
